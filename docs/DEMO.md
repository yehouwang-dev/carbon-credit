# 碳信用平台：2–3 分钟演示路线

## 启动

在项目根目录运行 `npm run demo`。浏览器打开后点「进入本地演示」。终端需要保持打开；用 Ctrl+C 结束本次启动的服务。

首次运行可能需要安装依赖和编译合约，建议演示前提前完成。演示使用本地 Hardhat 数据与演示账户。节点重新启动后，旧证书和交易记录不会保留。

## 演示前检查

- 页面显示「已连接」和「本地演示」，链 ID 为 31337。
- 新启动的链默认有 10,000 CC 账户余额、1 个已审核项目和 100,000 CC 金库流动性。
- 已运行过的链会保留当前数据，不要求数字每次相同。不要为了截图将它们描述为真实碳信用。
- 演示账户兼任管理员、审核员和发行员，方便展示流程；本次演示不代表由独立核验机构完成审核。

## 演示脚本

### 0:00–0:25：问题和整体界面

展示余额、发行量、核销量和项目数，说：

> 我想探索如何把项目记录、信用发行额度和核销记录关联起来。这个原型用 NFT 记录项目，用 ERC-20 演示信用流转；项目减排数据在这里是人为输入的示例。

### 0:25–1:10：提交与审核

在「注册碳项目」填写一个新的演示项目：

| 字段 | 演示内容 |
| --- | --- |
| 项目名称 | Demo Forest — Portfolio |
| 项目类型 | Forestry |
| 减排量 | 100 tCO₂e |
| 地点 | Hainan, China |
| 核验机构 | Demo Reviewer |
| 标准 | VCS（仅演示标签） |
| 年份 | 2026 |
| 证据文件哈希 | demo-evidence-001（虚构标识） |

点击「提交审核」，等待交易成功。到审核队列点击「批准」，记下「我的项目资产」里新生成的 NFT ID。首次演示通常是 2；重复演示时使用实际显示的 ID。

说：

> 审核通过后生成项目记录，发行量会受到该记录的额度约束。链上批准记录可以追溯，但不能证明演示资料真实。

### 1:10–1:45：关联项目发行

在「碳信用操作」选择刚才的 NFT ID，数量填 100，原因填 `Portfolio demo issuance`，收款地址留空。点击「铸造信用」，等待成功，展示项目的已发行量与剩余可发行量。

说：

> 这次发行关联到指定项目。项目额度用完后，再发 1 CC 会被合约拒绝。

时间允许时可尝试再发行 1 CC，展示失败提示；然后关闭提示。失败的操作不应改变余额或发行量。

### 1:45–2:30：核销与验证

保持同一个项目 ID，将数量改为 10，受益方填写 `Portfolio Demo`，原因填写 `Demo retirement`。点击「销毁信用」，等待成功，展示核销记录和项目剩余发行额度。

点击该记录的「证书」，打开下载的 HTML，复制其中完整的 Certificate ID。回到页面的「验证核销证书」粘贴这个 ID，点击「验证」。展示 10 CC、项目 ID 和受益方。

说：

> 核销生成唯一的链上记录，验证页通过合约查询这个 ID。下载的文件本身可以被编辑，因此应以查询到的链上数据为准。这验证的是原型内的核销记录，而非现实环境认证。

### 2:30–3:00：贡献与局限

> 这个项目把审核、关联发行和核销查询连接成一个可以复现的流程。目前仍有外部数据真实性、权限治理和安全审查方面的限制。我希望继续研究证据来源与核验流程如何影响记录的可信度。

说明你实际参与的设计、实现、检查工作以及 AI 辅助方式。多签和时间锁目前是单独的治理原型，不要把它们介绍成已经接管全部管理权限。

## 快速排障

- **本地链不可用**：确认 `npm run demo` 所在的终端仍然运行，重新运行命令后刷新网页并连接。
- **端口被别的应用占用**：启动器会提示具体端口，不会结束别的进程。可用 `DEMO_RPC_PORT=18545 DEMO_WEB_PORT=18080 npm run demo` 启动到其他端口（macOS/Linux）。
- **重复演示数据已有变化**：使用新生成的实际项目 ID，保留已有记录即可；启动器不会主动清空链。
- **暂停导致操作失败**：由本地管理员在紧急控制里恢复对应操作后再继续。

## Optional English opening

> This prototype explores traceability across project review, credit issuance, and retirement. Project NFTs define recorded issuance limits, while retirement creates an on-chain record that can be queried by certificate ID. The demonstration uses fictional data on a local development chain; it does not validate real-world emission reductions.
